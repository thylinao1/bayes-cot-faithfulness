THE CAUSE, and it is a data-tracking asymmetry, not a code defect. The gate
corpus is built from two banked transcript files named in
tests/test_jury_gate.py REPO_BANK:

  experiments/results/phase1-skeleton/qwen3-8b/arc_challenge/stated-hint/transcripts.jsonl
      NOT tracked, and never has been (`git log --all` on the path is empty).
  experiments/results/control_transcripts_llama-3.1-8b-instant.json
      TRACKED, 22 rows. It is load-bearing elsewhere: it is cited in
      PREREGISTRATION_jury_and_scale.md line 1298 and every id in
      experiments/jury/manipulation_split.json comes from it.

The fixture guards the all-absent case only:

    rows = sg.load_bank(REPO_BANK)
    if not rows:
        pytest.skip("banked transcripts are not present in this checkout")

In a fresh checkout `rows` is not empty, it is the 22 tracked rows, so the
fixture does not skip and the corpus builds 154 items (22 per class) against
a committed manifest, experiments/jury/gate_corpus_manifest.json, that records
483 items and 69 per class from 483 usable bank rows. The manifest's own note
says the corpus "is derived data under the gitignored experiments/results
tree", which is precisely why the 461-row phase1-skeleton file is absent while
the 22-row control file is not.

WHAT THIS LANE DID NOT DO. Fixing this means either changing the skip
condition to cover a partial bank, or changing what is tracked. Both are test
or data decisions outside a lint lane's remit (the lane's limits allow
lint-only edits inside test files and no logic changes), so nothing here was
touched. The jury lane or the orchestrator owns the call.
