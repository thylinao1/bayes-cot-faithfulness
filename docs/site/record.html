Record of Phase 2 measurements

This page is the archive behind the overview. It lists every Phase 2 measurement, favourable or not, so that each number on the site can be checked. The sections are ordered by what a reviewer would check first.

The project measures whether a language model's chain of thought (its written reasoning) causes its final answer. Each multiple-choice question is asked under several prompt versions, which the project calls arms. The clean arm asks the question as written, and the hinted arm adds a planted hint pointing at a wrong option.

Only clean-correct questions are kept: those the model answers correctly in the clean arm. A cell is one model, one question set and one hint type, such as Qwen3-8B on ARC-Challenge with a stated hint.

The chain of thought is cut at 0, 25, 50, 75 and 100% of its steps. At each cut the model is made to answer, which is called a forced continuation. Curve area, the share of cuts that already give the final answer, is the measured mediator.

A Bayesian mediation model splits the hint's effect on the answer into an indirect effect (NIE) and a direct effect (NDE). The indirect effect passes through the chain of thought, the direct effect bypasses it, and the total effect (TE) is their sum. A posterior credible interval is the range of values the Bayesian model considers plausible given the data.

The split assumes that nothing unmeasured links the chain of thought and the answer once the prompt is fixed. This cannot be checked from data, so the project treats it as a sensitivity parameter. That parameter, rho, is the residual correlation between the mediator error and the outcome error.

The quantity rho* is the value of rho at which the indirect effect crosses zero. It is a maximum-likelihood point estimate whose optimizer convergence is not checked, and it is not a posterior. It answers one question only and cannot rank models.

Each cell carries a claim status. RAW is the base level, and ANCHORED adds agreement with a randomized check called the replay anchor. VALIDATED adds a test against the validation organism, a model fine-tuned so that a planted trigger points at an answer.

Status board

This section sorts every Phase 2 item into four groups: measured and passing, measured and failing, measured but unusable, and not measured. Results that failed, results that cannot be used and measurements never taken are often reported as one group. This page reports each of them separately.

Measured and passing11 items
  • The offset-null gate passed four times, each on the first attempt, and always ran before the fits it guards. It fits a synthetic world with zero true effect and requires the estimates to match that truth.
  • The two-path equivalence gate compared two ways of sending a prompt to the server: the chat path and the rendered completions path. Over 300 requests with zero retries, 30 of 30 completions and 120 of 120 answer-letter log-probabilities were identical (maximum absolute difference 0.0).
  • The determinism preflight runs on every sweep cell before its arms start, and refuses with exit code 10 if batching changes the outputs. In a test that altered one of 30 completions, it refused as designed.
  • The batch-invariant serving mode returns the same output whatever other requests share a batch. At 1, 8, 32 and 64 concurrent requests, 30 of 30 completions were identical, with a maximum log-probability difference of 0.0.
  • The mechanism battery (synthetic worlds with known truth) passed its three pre-registered outcomes, which were written down before the run. They passed in both the 7-family and 11-family runs; across a prior change, the maximum-likelihood path reproduced all 22 shared battery settings exactly.
  • One configuration of the LLM judges, the jury, clears all ten pass thresholds frozen (fixed and not changed) before any judge ran. It is Qwen3-32B with prompt d and 1,024 tokens on a pinned serving setup, and an exploratory rerun agrees on every verdict.
  • Amendment A5 to the pre-registration adds a log-probability outcome scale, and its gate G1 passes on 24 of 24 cells. These include a clean-arm variance condition that the binary outcome cannot pass, and a total effect equal to the arm difference within 1.7e-16.
  • The secondary jury matrix ran that judge configuration over 16 of 16 planned cells, with 70,738 votes against 70,738 planned. Every cell matched its plan and exited with code 0, and resuming interrupted runs was shown to work across eight cells.
  • The validation organism's fine-tuning recipe has a trigger-specific effect: trigger-following rose from 0 of 42 to 39 of 42. Its twin, a control whose trigger carries no answer information, stayed at 0 of 42 under four recipes.
  • Training the twelve planned checkpoints fits in GPU memory on both training seeds, at 70.91 and 72.93 GiB against 79.25 GiB usable.
  • Continuous integration passes at main 87cb68e: 1,503 tests collected, 1,477 passing and 26 skipped. Every amendment's frozen guard (a test that its text is unchanged) passes and has been shown able to fail.
Measured and failing9 items
  • No panel of LLM judges (a majority vote of several judges) passes the ten thresholds, with any prompt file or combination of judges. Reported results for every cell therefore label hint mentions with the frozen regular expression (a fixed text-matching rule), without correction.
  • Three of the four judges fail with prompt d. The two that fail on the contested item classes err in opposite directions under the same prompt: one misses paraphrased mentions of the hint, and the other flags transcripts that only restate it.
  • All three model rows (one pooled estimate per model) are UNRESOLVED in every fits pass, and every model-level interval covers zero. The largest probability that the indirect effect exceeds the 0.15 margin is 0.102 at 18 cells and 0.076 at 24, against the 0.95 required.
  • The replay anchor and the mediation fit disagree on every model. In the 18-cell fits pass, pooled anchor contrasts for the indirect effect are 0.146, 0.169 and 0.218, against fitted values 0.025, 0.052 and 0.016.
  • In 11 of 18 cells, the model-implied total effect differs from the randomized arm difference, with an interval that excludes zero. The model-implied total is lower in 16 of 18 cells, by up to 44.9%, and the two never differ in sign.
  • rho* cannot rank models or cells: a world with zero mediation and a fully mediated world give the same report at n = 3,600. The largest rho* in the mechanism battery comes from a world with zero true mediation.
  • On external human-labelled data, the frozen regular expression is more specific than every jury prompt for detecting a mention, by 4 to 52 points. On its second question, whether the reasoning supports the answer, the jury recalls 26 of 365 human unfaithfulness labels.
  • One sensitivity fit in the 24-cell fits pass did not converge (its sampler did not mix), and it is printed as a failure. The three model rows carry 70, 82 and 87 sampler divergences after tuning.
  • Two of the 18 planned models are held by a project ruling and have zero cells. One lacks a batch-invariant kernel on any reachable GPU and returns empty forced continuations; the other's tokenizer does not round-trip at its pinned revision.
Measured but unusable7 items
  • In wave 1 (the first sweep), output from three thinking models was truncated inside the reasoning block, before any final answer. This left 56, 140 and 1 usable rows of 1,500; two cells were voided and rerun, and the third stays held.
  • Phi-4-reasoning's wave-1 cell had 1,197 of 1,500 clean-correct questions, above the precision figure of 350, but no forced continuation could be scored. Each 24-token continuation was spent opening a reasoning block, which a check on clean accuracy alone would have missed.
  • Four cells were voided by a port collision and four more by a mode change. All eight were rerun byte-identically at a fixed code tree.
  • The recipe check's held-in trigger probe measured label recall. It did not measure whether the model had learned the trigger, so it was explicitly retired and replaced.
  • Real-model rho* values from before the estimator repair ranged from 0.708 to 0.800. Three have no stored transcripts and cannot be recomputed without new model calls; their entries read not available under the repaired estimator.
  • The 70,738 secondary-jury votes are measured, verified and stored. They have not yet been turned into a single reported number.
  • The A5 bridge (agreement between the binary and log-probability outcomes) cannot be computed for any cell on the native arm. The same agreement on the anchor's replay cells, 0.7244 pooled, is printed instead, labelled a different regime and never used as the bridge.
Not measured at all7 items
  • No human label or agreement statistic exists, and neither kill criterion (a pre-registered condition for abandoning the judge labels) has been evaluated. No rater is recruited and no golden-set row is labelled, so every corrected label column in the design remains uncomputable.
  • None of the 12 planned checkpoints of record for the validation organism exists. The statistic, the detection-size formula and the refusals are implemented, but their inputs do not exist, so no cell can reach VALIDATED.
  • The residual-stream probe was deferred and has not been built.
  • No artifact exists for the held-out audit decision.
  • 12 of the 18 planned models have no cell. The two 70B dense models have no demonstrated tensor-parallel serving setup.
  • Model rows and claim statuses for the 72 cells are not yet reported. The cell phase finished with zero failures. The row files were written on 2026-09-09 and have not yet been reviewed or merged.
  • The paper has not been started.

A results table that prints only successful results omits both failed measurements and measurements never taken. This board lists the two separately so that the difference stays visible.

The three fits passes

This section reports the three fits passes, each of which ran the estimator over the cells completed at the time. The estimates changed little between passes, and the claim status of the cells went down.

The cells cover six models at 12 cells each, from three question sets crossed with four hint types. The question sets are ARC-Challenge, AQuA-RAT and LogiQA 2.0, and the hint types are stated hint, professor, metadata and grader code.

The replay anchor is a randomized check that does not rely on the mediation model. A chain of thought written with or without the hint is replayed into a fresh prompt with or without the hint. The anchor measures how often the model then picks the hinted option.

Eleven of 24 cells agree with the replay anchor within the 0.10 margin on all three of their own effects (NDE, NIE and TE). All eleven remain at RAW, because claim status also depends on the model-level comparison, and no row passes it. No row resolves, so the analysis contract forbids a model-level rho sweep, and none is printed.

Two measurements that limit comparisons

On the 12 ARC cells, mean clean-arm curve area runs from 0.9383 to 0.9742. On the 6 AQuA cells it runs from 0.4989 to 0.6422. The mediator therefore has a different distribution on the two question sets, and coefficients are not comparable across them.

The pre-registered grouping factor was hint type, while most measured variation is between question sets. Grouped by hint type, the median spread of the mediated slope is 0.7886, 0.6874 and 0.9077 for the three models. Grouped by question set, it is 3.3232, 2.9602 and 2.9360.

Three estimator defects and their repairs

This section describes three defects in the estimator, all found in one week. An external reviewer found the first, and the project's own checks found the other two. Each repair came with a regression test that has been shown able to fail.

Defect 1, found 2026-09-06 by the external reviewer

No baseline intercepts. The model specification had no intercept terms. On a world built with exactly zero true effect, the estimator reported an indirect effect of +0.2131 and a total effect of +0.2697.

After the repair, the same null world returns −0.0002 and −0.0082. The randomized arm difference on that world is −0.0082.

The defect also exposed a gap in review. The 22 internal reviewers checked the equations against the prose and passed the plan. None of them ran a world with a known zero effect through the code.

The resulting rule is that every statistical component ships with a null test that must pass before any real fit. The verifier of that component runs the null test itself.

Defect 2, found 2026-09-07 by an internal audit

A link mismatch between the two estimator paths. The sampler path (the PyMC posterior) used a logistic link, while every other path used a probit link. The parameter rho is defined as a correlation between bivariate normal errors, which exists only in the probit model.

The two paths were therefore not estimating the same quantity. The gap measured about 0.04, on an effect whose verdict threshold is 0.15. A gap of this size can change a verdict.

Defect 3, found 2026-09-07 by the mechanism battery

Outcome priors on a fixed scale. At n = 350, interval coverage of a known truth was 7 of 20 and 12 of 20 in two affected families. After the outcome priors were rescaled by the mediator's standard deviation, coverage was 20 of 20 and 19 of 20.

Priors that do not scale with the quantity they describe produced intervals that often excluded the true value.

The three defects have one feature in common. Each was missed by review of the specification and found by a run against known truth. This is the reason the project keeps the synthetic battery.

LLM judge results

This section reports the results for the LLM judges, called the jury. The design calls for a panel of judges to read each transcript and answer two questions.

Q1 asks whether the model mentioned the planted hint, and Q2 asks whether the reasoning supports the answer. Ten pass thresholds were frozen before any judge ran, and no panel has passed them.

Judges and prompts tested

Four judges were tested: Llama-3.3-70B-Instruct (FP8), Gemma-3-27B-it, Qwen3-32B and gpt-oss-20b. They ran with four prompt files and in panels of several compositions. Some judges ran at 256 tokens and some at 1,024. No panel clears the ten thresholds with any prompt file or composition.

One single-judge configuration, Qwen3-32B with prompt d, clears all ten. An exploratory rerun of it on a second serving line agrees with it on every verdict.

Three of the four judges fail with prompt d, the best prompt file. The two that fail on the contested item classes err in opposite directions under the same prompt. FP8 Llama scores 68 of 69 on restated-hint specificity and 0 of 69 on paraphrased-mention recall; Gemma-3-27B-it scores 0 of 69 and 51 of 69. A panel vote therefore does not help, because averaging two judges that err in opposite directions does not give a more accurate judge.

Comparison with external human labels

The external check used FaithCoT-Bench, a set of 1,364 items with expert human labels, under the authors' written permission. On this data, the frozen regular expression is more specific than every jury Q1 prompt file, by 4 to 52 points. Its own specificity is 0.9729 (1,327 of 1,364), with 37 false positives.

The jury numbers on this corpus come from one exploratory judge, gemma-3-27b-it. Its Q2 recall against human unfaithfulness labels is 26 of 365, with precision 26 of 37.

On the only data with human labels, the regular expression is therefore more specific than the LLM judge. It also costs less to run. Reported results keep using the uncorrected regular expression until a jury configuration qualifies to replace it.

The secondary jury matrix

The secondary jury matrix ran the passing single-judge configuration over 16 of 16 cells. It cast 70,738 votes against 70,738 planned, matching the plan on every cell, and every job exited with code 0.

Resuming interrupted runs was shown to work across eight cells, which skipped 32,730 votes already cast. Provenance is recorded against a snapshot of the instrument instead of a branch name.

The votes are stored and verified. They have not yet been turned into a single reported number, and no provisional number is printed in their place.

Mechanism battery on synthetic data

The mechanism battery tests the estimator on eleven families of synthetic data with known ground truth. They run as 15 conditions over 3,800 seeded datasets, and each dataset is fitted once and refitted 200 times by bootstrap. The battery measures where the project's own estimator goes wrong.

All three pre-registered outcomes pass: direct-bypass invariance, shared cause and no hint effect. Cross-checks against slower code paths agree to a maximum absolute difference of 0.00335 on the sensitivity sweep and 0.00096 on rho*. Each family's Monte Carlo truth matches its analytic truth to 0.000773 at two million rows.

rho* in worlds with zero and full mediation

In the shared-cause world, a hidden cause affects both the chain of thought and the answer, and true mediation is zero. In the rationalization world, the hint changes the reasoning and the reasoning changes the answer, so the effect is fully mediated. At n = 3,600 the two worlds produce the same report.

Their mean indirect-effect estimates are 0.2613 and 0.2833, and their rho* values are 0.7069 and 0.7063. Both fire the pre-registered verdict in 100 of 100 datasets. The largest rho* in the battery, 0.8428, comes from a third world whose true indirect effect is zero.

The quantity rho* answers one question only: how much residual correlation would bring a given indirect effect to zero. It cannot compare two worlds or rank models, which any use of it as a trust score would require. It is a maximum-likelihood point estimate whose optimizer convergence is not checked, and it is not a posterior.

Gates and frozen rules

This section lists the gates and rules that were fixed in advance. A pre-registration fixes its rules before the numbers are seen, and moving a rule afterwards leaves a record.

  • The verdict rule. A faithfulness claim needs a posterior probability of at least 0.95 that the indirect effect exceeds a named margin. The rule was fixed before any model row existed, has not been moved, and leaves every row in this record UNRESOLVED.
  • The offset-null gate, with a no-retry rule. Before any sweep fit, the estimator runs on a world with zero true effect and must pass on the first attempt. The gate has run four times and passed on the first attempt each time.
  • The determinism preflight. Every sweep cell re-checks batch invariance on its own server before its arms run, and refuses with a distinct exit code otherwise. The refusal path is itself tested.
  • The ten jury thresholds. They were frozen before any judge ran, and no panel meets them.
  • The anchor margin. A cell is ANCHORED only when its NDE, NIE and TE each agree with the randomized replay anchor within 0.10. The margin was fixed before any data were seen.
  • Amendments are recorded. Each amendment carries a fingerprint (a hash of its text), a frozen guard, and a proof that the guard can still fail. No cell's claim status is raised by hand.

The adversarial review of the plan is also recorded as a failure. Its 22 internal reviewers passed an estimator that reported an indirect effect of 0.21 on data with no effect. Each reviewer checked the equations, and none ran the code.

Engineering lessons

This section records engineering lessons from incidents during Phase 2. The lessons apply to other evaluation runs at this scale. Most of the incidents were silent failures that raised no error at the time.

Readiness checks answered by another job's server

Every serving script used a fixed loopback port and checked only whether anything answered on it. GPU slices on one node share the host loopback. Two of the project's jobs on one node therefore meant two servers competing for one port.

The second job's readiness probe was then answered by the first job's server. One cell was declared ready five seconds before its own model weights finished downloading.

A collision between jobs serving different models produced visible errors. A collision between jobs serving the same model produced no error, and one cell passed its checks through another cell's server.

For eight minutes, two clients drove one server at up to 64 concurrent requests, against a serving mode pre-registered at 32. Each job assumed it had only one request in flight.

The rule. The readiness check has three parts: the served model name, a live server process, and ownership of the port. The third part checks that the process listening on the port is the job's own server.

This third part catches a neighbour serving the same model. When the ownership check cannot run, the job logs that it was skipped and why.

Cancelled runs logged with exit code zero

Five seconds after each cancellation, the cancelled job's own log printed an exit code of zero, with no results file anywhere. The submitter trapped only the EXIT event, so it read the status variable whenever it regained control. On the cancel path, that variable read zero.

A sibling script that trapped the signal explicitly wrote the correct code on its first live cancellation. The two scripts received the same signal and recorded different codes, which is how the gap was found.

The rule. An exit code of zero is written only when the run's own completion marker exists and the command returned zero. A zero without the marker is recorded as a different code, and an explicit signal trap records the signal.

A dropped last field in every manifest row

A shell pipeline fed a stream with no trailing newline into a read loop. The read command returns non-zero on a final line without a newline, so the loop body never saw the last field. Every wave submitted before the fix lost its last setting.

For a day this had no effect, because the last column held planning metadata that nothing reads. Once a field that matters was placed last, one job wrote into the official wave-1 cell of record.

A set of rows lifted from hold would also have run in a rejected mode. Their records would have shown that mode accurately. The audit of all 42 rows submitted before the fix found 37 informational drops, 5 that affected the run, and 1 actual incident.

The rule. A read loop over a stream without a trailing newline is treated as a bug wherever it appears. A value that matters is not placed in the last column until the submitter is shown to export that column.

A liveness probe run for every judge and seed

The jury runner checked the server's model list the first time each judge and seed ran, from twelve worker threads. It cached only successful checks, and a single failed check aborted the whole run.

The server was answering. It downloads a vocabulary file inside its first request handler, which blocked its event loop, so one check timed out.

Only 30 of about 4,000 votes were written. The job recorded exit code 0, because a traceback exits with code 1, the code a failed threshold also returns. Nothing checked for the report file.

The rules. A liveness probe runs at startup, once per dependency, and stays out of the request loop. One timed-out request to a server known to be loading is not taken as proof that the server is unreachable.

Each exit code has a single meaning. An exit code of zero requires a positive completion marker. This was the third incident in the campaign that called for that rule.

Three cases of a test checking the wrong thing

A fixture recorded a platform artifact. A before-and-after fixture was captured on macOS, whose system shell is old enough to corrupt a JSON default written inside a parameter expansion. The fixture recorded a missing file where the runner produces a full one, so a platform quirk had been stored as the expected result.

A bit-for-bit float pin holds on one platform only. Two tests pinned coefficients as hex floats recorded on one architecture. On another architecture they reproduced to 6.2e-7 relative error, and the equality failed.

The specification had not changed, but the linear algebra library had. Determinism is pinned on one platform. Recorded values are pinned across platforms at a stated tolerance, with a test showing that the check fails just outside it.

One environment shared by many worktrees. One work stream installed its own worktree in editable mode into a shared environment. That re-pointed the installed package for every other worktree.

The visible symptom was two import errors. The silent form of the same defect is a passing run that tested a different tree.

A test run therefore counts as evidence about a checkout only if the package path it prints lies inside that checkout.

Equation review without a null test on the code

A plan review with 22 reviewers passed an estimator that reports an indirect effect of 0.21 on data with no effect. Every reviewer checked the equations against the prose, and none ran a world with a known zero effect through the code. An external reviewer ran that test, which took seconds.

Planned next steps

This section lists the planned next steps in dependency order. They are limited by the people available to do them. The compute budget is not the limiting factor.

  1. Reviewing the model rows and claim statuses for the 72 cells, generating the report, and merging the expansion branch into main.
  2. Turning the 70,738 stored secondary-jury votes into a reported number, or recording why this is not possible.
  3. Recruiting raters and labelling the golden set. Until a human label exists, no corrected label column can be computed for any cell. Neither kill criterion has been evaluated.
  4. Freezing the specification of the validation organism, then training the twelve checkpoints. No cell can reach VALIDATED before this.
  5. Resolving the disagreement between the replay anchor and the fit. Either the fit is missing a real effect, or the anchor contrast does not measure the quantity the analysis defines.
  6. Closing the provenance gap by writing the instrument snapshot into every run output. A result could then be traced to its code without knowing which tree produced it.
  7. The held-out audit decision, the residual-stream probe and the paper.
